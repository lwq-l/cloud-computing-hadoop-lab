# 第5章实践作业（三）：计算虚拟化与 Docker 资源隔离综合实践

> 课程：《云计算技术及应用》；适用：金融学、投资学等本科学生；实验时间：180分钟（可分两次完成）；总分：100分。  
> 平台：CNB 云原生开发（浏览器 WebIDE + Linux 终端）；实验方式：个人独立完成；提交：PDF实验报告。  
> **本章不要求学生在电脑上安装 Linux、虚拟机、Docker Desktop 或 KVM；也不创建真实 Xen/KVM 虚拟机。**

## 一、实验依据与学习目标

本作业紧扣课堂《第5章 计算虚拟化》PPT的五个模块：

1. **计算虚拟化概述**：资源抽象、虚拟化层、裸金属与寄居虚拟化。
2. **CPU虚拟化**：x86特权级、全虚拟化、半虚拟化、Intel VT/AMD-V。
3. **内存虚拟化**：Guest虚拟地址(GVA)、Guest物理地址(GPA)、机器地址(MA)，影子页表、EPT。
4. **I/O虚拟化**：设备模拟、前后端驱动、I/O透传。
5. **典型产品**：Xen和KVM。

在此基础上增加**Docker容器与虚拟机区别**的动手环节。Docker依靠操作系统内核提供进程隔离、命名空间和资源控制，并非真正的 Hypervisor；本实验通过容器实际观察 CPU/内存限制、容器文件系统和数据卷，帮助理解资源管理思想，**不能把容器参数误当成真实虚拟机的硬件辅助虚拟化实验结果**。

本作业不会评价学生能否安装虚拟机或访问物理宿主机。学生仅需要有权限的独立 CNB 工作区，并在工作区终端运行命令。

## 四、任务二：虚拟化原理与架构图（15分，25分钟）

请使用 PPT、Word 绘图工具或手绘（照片须清晰）绘制一张分层架构比较图，包含三列：

- **裸金属虚拟化**：物理硬件 → Hypervisor（例如 Xen）→ Guest OS → 应用；
- **寄居虚拟化**：物理硬件 → Host OS → 虚拟化软件 → Guest OS → 应用；
- **容器化**：物理硬件 → Host OS/内核 → 容器运行时 → 相互隔离的应用（共享内核）。

图旁用150字以上解释：为什么“每个容器有自己的文件系统视图”和“每台虚拟机有完整 Guest OS”不是同一回事？再回答：

1. x86 的 Ring 0 和 Ring 3 分别典型执行哪类代码？
2. 全虚拟化、半虚拟化与硬件辅助虚拟化如何处理特权操作？分别说出一个关键机制，例如 Trap-and-Emulate、Hypercall、VMX。
3. KVM 与 Xen 的特点是什么？注意 KVM 基于 Linux 内核和硬件虚拟化支持；Xen 涉及特定的管理域 Dom0。

**提交：架构图1张和上述简答题。** 本任务为概念分析，无需在 CNB 内安装 Xen、KVM 或运行真正的 Guest OS。

## 七、任务五：CPU和内存资源限制（20分，35分钟）

### 5.1 创建有资源限制的容器

~~~bash
docker run -d --name ch5-limited --cpus=0.50 --memory=128m --pids-limit=64 alpine:3.22 sh -c 'while :; do sleep 10; done'
~~~

查看创建参数：

~~~bash
docker inspect --format 'NanoCpus={{.HostConfig.NanoCpus}} MemoryBytes={{.HostConfig.Memory}} PidsLimit={{.HostConfig.PidsLimit}}' ch5-limited
~~~

理论上可以看到 NanoCpus=500000000、MemoryBytes=134217728、PidsLimit=64。参数是**上限**，不是容器当前已经使用这么多资源。

### 5.2 CPU虚拟化相关观察

~~~bash
docker exec ch5-limited sh -c 'echo "cpu.max:"; cat /sys/fs/cgroup/cpu.max 2>/dev/null || echo "not cgroup v2"'
~~~

~~~bash
docker stats --no-stream ch5-limited
~~~

**截图7**：Docker CPU 配额参数；**截图8**：cpu.max 输出或标注当前 cgroup 版本不支持该文件。

请解释：--cpus=0.50 是否表示“获得一个真正独立的半颗物理CPU”？为什么它更接近CPU时间份额/配额控制，而不是 Xen/KVM 的 Guest vCPU 虚拟化？

### 5.3 内存虚拟化相关观察

~~~bash
docker exec ch5-limited sh -c 'echo "memory.max:"; cat /sys/fs/cgroup/memory.max 2>/dev/null || echo "not cgroup v2"'
~~~

~~~bash
docker stats --no-stream ch5-limited
~~~

**截图9**：Docker MemoryBytes 参数；**截图10**：memory.max 或内存使用率监控。

请解释：--memory=128m 表示允许使用的内存额度，不等于开机时预先消耗128MB；同时要区分**容器内存限制**和**虚拟机内存地址映射（影子页表/EPT）**。

**安全要求：不运行压力攻击、内存耗尽、fork bomb 或高负载死循环，不使用 --privileged 或 --network=host。**

## 八、任务六：I/O与 Docker 数据卷（15分，30分钟）

先看当前容器可见文件系统：

~~~bash
docker exec ch5-demo sh -c 'ls /; ls /proc | head'
~~~

建立一个专用教学卷（不会影响其他容器）：

~~~bash
docker volume create ch5-data
~~~

让一个临时容器写入该卷：

~~~bash
docker run --rm -v ch5-data:/lesson alpine:3.22 sh -c 'echo "chapter5-volume-ok" > /lesson/record.txt'
~~~

创建另一个临时容器读取同一个卷：

~~~bash
docker run --rm -v ch5-data:/lesson alpine:3.22 cat /lesson/record.txt
~~~

~~~bash
docker volume inspect ch5-data
~~~

**截图11**：第二个临时容器读取 chapter5-volume-ok；**截图12**：数据卷信息。

分析：

1. 临时容器退出后数据仍能被下一容器读取，说明了容器文件系统与 Docker 卷的什么关系？
2. 为什么 Docker 数据卷不等于课堂中讲的硬件 I/O透传？
3. 对照PPT，I/O全虚拟化、前后端半虚拟化、I/O透传各有什么优缺点？

注意：卷存储属于 Docker 守护进程所管理的环境，**不保证 CNB 工作区关闭、回收后数据仍能保留**。本实验只验证“不同容器共享同一个卷”，不把它视为长期备份。

## 十一、容易出现的问题

| 现象 | 正确处理 |
|---|---|
| docker: command not found | 联系教师检查 CNB 自定义镜像和 docker 服务 |
| Cannot connect to Docker daemon | 联系教师检查 .cnb.yml 的 docker 服务，勿自行安装 daemon |

| Conflict: container name already in use | 用 docker ps -a 检查是否自己上次创建的 ch5-demo/ch5-limited，不要删除其他学生的容器 |
| Permission denied | 使用 bash scripts/virtualization/cleanup.sh 形式执行 |

| free -h 与 Docker memory 限额不一致 | 可能是工具显示宿主信息，应以 Docker inspect 与 cgroup 为主要观察点 |
| 退出云端环境后卷消失 | Docker 卷不保证跨工作区回收永久保留；立即整理并下载报告 |

## 十二、教学边界

- 课堂内容中的 **Xen / KVM / VT-x / AMD-V / 影子页表 / EPT / I/O透传** 是理论与示意，不要求操作硬件虚拟机。
- 通过 **Docker + cgroups + volume** 的实验只验证容器管理功能；**容器并不是一台新的物理服务器**。
- 第四章的三个DataNode属于同一开发环境的逻辑服务进程，不是三台独立物理服务器；第五章容器实验也不宣称物理级故障隔离。
- CNB支持按需创建和回收工作区，网页终端不能作为长期数据仓库。学生应边做边保留截图，报告存到自己的电脑和学习通。
- 正式发给学生前，请教师在 CNB 新工作区实测 Docker daemon、Alpine镜像拉取/构建、docker run、cgroup限制及Docker卷；**仅通过脚本静态检查不等于本章上机验收**。
